# Как запустить готовый сценарий

**Читайте, если** запускаете стенд или проверяете воспроизводимость · **Связано:** [Пайплайн](data-pipeline.md)

---


## Что нужно для первого запуска?

Docker с Compose. Первый build скачивает образы и зависимости; готовое приложение работает
без платных ключей и внешних модельных API. `.env` не требуется.

## Как запустить разработку?

```bash
docker compose up --build -d
docker compose ps
```

Откройте `http://localhost:8080`. `PORT=8081` меняет только внешний порт frontend.
Backend доступен через `/api/v1` на том же адресе. В Compose его порт наружу не публикуется.
`docker compose down` останавливает эти два сервиса и не удаляет исходные данные.


```bash
cd backend
uv sync
uv run uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000
```

Во втором терминале:

```bash
cd frontend
npm ci
npm run dev -- --host 127.0.0.1 --port 8080
```

Vite проксирует `/api` на `http://localhost:8000`. `API_URL` меняет upstream разработки,
`API_SCHEMA_URL` — источник генерации типов. `SITE_URL` используется при сборке метаданных сайта.
При замене артефактов перезапустите backend: файлы читаются как неизменный снимок и кешируются.


## Какие проверки существуют?

| Команда | Что проверяет |
| --- | --- |
| `cd frontend && npm run verify` | Правила, типы, lint, unit-тесты и production build |
| `cd backend && uv run ruff check . && uv run mypy .` | Стиль и типы backend |
| `cd backend && uv run pytest tests/unit` | Бизнес-правила, HTTP, репозитории и импорты |
| `uv run python -m unittest discover -s tests` | Модель, ожидание, Palma, сжатие, сезонность и восстановление данных |
| `uv run python etl/validate_indices.py` | Полный локальный расчёт индексов; требует DuckDB из пайплайна |

Desktop-сценарий на работающем стенде:



Мобильные проверки не проводились. Внешние расписания и проходимость не проверяются
автоматическими тестами. Полная пересборка требует root-окружения `uv sync --python 3.12`,
свободного места для исходников и вычислений; параметры приведены в пайплайне.

### Локальный дорожный граф

После восстановления `data/graph_ru` и `data/casechamp.duckdb` из data-20261107:

```sh
cd backend
GRAPH_DIR="$(pwd)/../data" CHAT_ENABLED=true PYDANTIC_AI_NO_BANNER=1 uv run uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8001
```

Фронтенд, проксирующий API8001: `API_URL=http://127.0.0.1:8001 npm run dev -- --host 127.0.0.1 --port 5187`
из `frontend/`. Во вкладке «Сценарий» выберите регион и дороги, задайте множитель скорости,
запустите пересчёт. Первый точный расчёт проверяет базу; это минуты, не мгновенный ответ.
Завершённые результаты находятся в `data/scenario-results/`. Исходная DuckDB не модифицируется.

Предрасчёт для быстрых сценариев добавления связи:

```sh
cd backend
PYTHONPATH=src uv run python -m app.adapter.road_graph.precompute --data-dir ../data
```

Команда проверяет базовые индексы всех 84 записей регионов снимка (82 региона карты)
и сохраняет матрицы до 180 рынков в `data/scenario-cache/`. Backend загружает их в память
при старте. Ключ кеша учитывает версию метода, размеры и время изменения исходных файлов.
Подготовленный CSR граф сохраняется в `data/scenario-results/`. На проверенном снимке
матрицы занимают 268 МБ, CSR около 228 МБ; оперативная память дополнительно нужна исходному
графу и рабочим массивам. Матрица расстояний между всеми 7 млн узлов не строится.

Для новой связи между подготовленными рыночными узлами полный поиск маршрутов не нужен.
Для другого узла один поиск выполняется при первом использовании; проекции расстояний
сохраняются на диск и используются повторно. Быстрый путь поддерживает одну двустороннюю
связь на базовой сети. Изменение существующих дорог и сезонные сценарии пока считают полный граф.

Приложение использует общероссийский атлас. Во всех региональных карточках раздел
«Сценарии» открывает карту с выбранным регионом. Если `GRAPH_DIR` не задан, расчёт
возвращает явную ошибку недоступности данных; географического исключения для региона нет.
