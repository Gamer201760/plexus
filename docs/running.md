# Как запустить готовый сценарий

> Для запуска нужны Docker и уже загруженный снимок ClickHouse.
> Локальная база сохраняется в именованном volume; исходные DuckDB и JSON приложению не нужны.

**Читайте, если** запускаете стенд или проверяете воспроизводимость · **Связано:** [Хранилище](clickhouse.md), [Пайплайн](data-pipeline.md)

---

## Как запустить Compose?

Пароль задаётся в исключённом из Git `.env.analytics`. Пример переменных есть в
`.env.example`. На текущей локальной машине база уже загружена. Чистый checkout
без volume не содержит данных: первоначальная загрузка описана в [хранилище](clickhouse.md).

```sh
docker compose --env-file .env.analytics up --build -d
docker compose --env-file .env.analytics ps
```

Откройте `http://localhost:8080`; переменная `PORT` меняет внешний порт frontend.
API доступен через `/api/v1`. Compose поднимает frontend, backend и ClickHouse.
`docker compose --env-file .env.analytics down` останавливает проект и сохраняет volume.
Производные кэши Compose находятся в отдельном volume `plexus-analytics_plexus_runtime`.
Первый запуск с пустым кэшем строит CSR из БД; локальные кэши разработки не монтируются.
База опубликована только на `127.0.0.1:18123`; внутри Compose backend использует
`http://clickhouse:8123`. Расчёты не требуют платных модельных API.

## Как запустить локальную разработку?

Из корня репозитория:

```sh
docker compose --env-file .env.analytics -f compose.analytics.yaml -p plexus-analytics up -d
set -a
source .env.analytics
set +a
cd backend
uv sync
GRAPH_DIR="$PWD/../data" CHAT_ENABLED=true uv run uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8001
```

Во втором терминале:

```sh
cd frontend
npm ci
API_URL=http://127.0.0.1:8001 npm run dev -- --host 127.0.0.1 --port 5187
```

`GRAPH_DIR` задаёт каталог производных численных кэшей. Он не содержит обязательных
DuckDB или Parquet. Без `GRAPH_DIR` атлас и дорожный слой доступны, а расчётные маршруты
возвращают явную ошибку. При недоступности ClickHouse API возвращает 503; перехода
к файлам нет. `/health` проверяет процесс, а не наличие данных в БД.

`API_URL` меняет upstream Vite, `API_SCHEMA_URL` — источник генерации типов.
`SITE_URL` задаётся при сборке метаданных. После обновления снимка перезапустите API,
чтобы сбросить его справочники и массивы в памяти.

## Какие проверки существуют?

| Команда из `backend/` | Что проверяет |
| --- | --- |
| `uv run ruff check . && uv run mypy .` | Стиль и типы |
| `uv run pytest tests/unit` | Бизнес-правила, HTTP-контракты, типизация записей и импорты; БД не нужна |
| `uv run pytest tests/integration` | Настоящий ClickHouse: атлас, поиск, геометрия, матрицы и сохранённые результаты |

Перед интеграционными тестами экспортируйте переменные из `.env.analytics`, как выше.
Отсутствие настроенного хранилища вызывает явную ошибку. Проверка frontend:
`cd frontend && npm run verify`. Мобильные проверки не проводятся.

Полная пересборка исходных индексов относится к [ETL-пайплайну](data-pipeline.md),
требует восстановленного набора источников и отдельного root-окружения.
Она не входит в запуск API из базы.

## Как пересоздать производные кэши?

С экспортированными переменными ClickHouse, из `backend/`:

```sh
PYTHONPATH=src uv run python precompute.py --data-dir ../data
```

Команда читает подробный граф и матрицы из ClickHouse, проверяет базовые индексы
84 записей регионов снимка и сохраняет матрицы до 180 рынков в `scenario-cache`.
CSR графа находится в `scenario-results`. Эти файлы можно удалить и построить заново;
версия снимка в БД определяет пространство ключей кэша.

Для новой связи между подготовленными рыночными узлами полный поиск маршрутов не нужен.
Для другого узла поиск выполняется при первом использовании, результат кешируется.
Изменение существующей дороги и сезонный сценарий пока пересчитывают полный граф;
это может занимать минуты. Задания и подробные результаты сохраняются в `plexus_state`.

Лаборатория `/scenarios` использует отдельные таблицы `plexus_scenario`. В локальном
снимке её исходных матриц не было, каталог остаётся пустым и API отвечает 503.
Сценарии изменения дорог и добавления связи работают через расчётный граф.
