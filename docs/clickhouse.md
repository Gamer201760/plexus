# Рабочие данные в ClickHouse

> API читает атлас, граф, матрицы времён и сохранённые расчёты из ClickHouse.
> JSON атласа разобраны в типизированные таблицы. Исходные DuckDB, Parquet и JSON
> не нужны для запуска; на диске остаются производные численные кэши и материалы источников.

**Читайте, если** запускаете приложение или проверяете хранение и скорость · **Связано:** [Запуск](running.md), [Архитектура](architecture.md)

---

## Что хранится в базе?

| База | Данные |
| --- | --- |
| `plexus_casechamp` | 20 таблиц расчётного снимка; матрица времён содержит 83 845 118 строк |
| `plexus_additional` | 26 таблиц населённых пунктов, компаний и дополнительных источников |
| `plexus_graph` | Узлы, рёбра, точки, дороги; подготовленная геометрия и справочники поиска |
| `plexus_atlas` | Типизированные регионы, связи, населённые пункты, экономика, границы, аэропорты, индексы и источники |
| `plexus_state` | Задания, результаты анализа, геометрия и эффекты по населённым пунктам |
| `plexus_scenario` | Схема отдельной лаборатории сценариев; локальный набор её матриц отсутствует |

50 исходных таблиц содержат 125 290 049 строк. Дополнительно сохранены 95 документов
атласа с SHA-256: это архив происхождения данных в БД, рабочие запросы его не разбирают.
Таблицы `atlas_indices` и `atlas_exported_indices` сохраняют обе версии модели:
246 записей расчётного снимка и 410 записей опубликованного экспорта. API использует
первую, согласованную с загруженным графом; перенос не меняет формулу и нормировку.

Исторические даты вне диапазона Date32 сохранены строками ISO. Массивы из исходных
таблиц DuckDB сохранены без потери NULL; в этих архивных таблицах некоторые поля-массивы
представлены JSON-строками. Рабочие связи, геометрия и результаты расчётов имеют
численные поля, `Array` и `Tuple`, а не JSON-тело на каждую запись.

## Почему запросы читают меньше строк?

| Операция | Организация данных |
| --- | --- |
| Матрица региона | Ключ `(season, point_id, city)`; множество point_id региона передаётся в `IN`, до чтения матрицы |
| Карточка и населённые пункты региона | Ключ начинается с `region_id`; фильтрация выполняется в SQL |
| Связи региона | Ключ `(region_id, mode, season, id)` |
| Поиск населённого пункта | Нормализованное имя и `ngrambf_v1`; точный `LIKE` проверяет кандидатов |
| Дорога по OSM ID | Проекция `ways.by_osm_id`, отсортированная по `way_id` |
| Дорожный коридор | Справочник `road_lookup` по нормализованному названию; проекция `ways.by_reference` по `ref` |
| Рёбра дороги и координаты узлов | Ключи `(way_idx, src, dst)` и `node` |
| Окно карты | Подготовленные линии, класс дороги, географические ячейки и minmax-индексы bounding box |
| Сохранённый результат | Ключ ID задания; для подробностей — `(analysis_id, way_id)` |

Индексы выбраны по реальным условиям запросов. Bloom-фильтр может пропустить лишний
блок, но окончательный предикат не допускает лишних результатов. Строка поиска короче
трёх символов не получает преимущества триграммного индекса. Небольшие неизменяемые
справочники также кешируются в процессе API. После замены снимка API нужно перезапустить.

**Измерено 10.11.2026:** ClickHouse 25.6.13.41, локальный Docker, 3 CPU и лимит 3 ГБ,
две серии по три последовательных запроса. Время включает HTTP, получение и декодирование
результата. Вторая серия совпала со сборкой Docker, поэтому задержки приведены обе.

| Запрос | Прочитано строк | Медианы двух серий |
| --- | ---: | ---: |
| Матрица Владимирской области, 454 680 результатов | 475 136 | 0,314 / 0,950 с |
| Один OSM way ID | 32 768 вместо 4 301 210 без проекции | 0,017 / 0,007 с |
| Населённые пункты Владимирской области | 2 952 из 155 412 | 0,021 / 0,017 с |
| Поиск «владимир» | 84 388 вместо 155 412 без вторичного индекса | 0,038 / 0,028 с |
| Поиск названия трассы «м7» | 256 из 194 038 | 0,004 / 0,002 с |

Планы `EXPLAIN indexes=1` подтвердили отсечение блоков. Это локальные измерения SQL/API,
а не FPS карты и не сравнение с PostgreSQL. Поиск по всем регионам всё ещё читает
значительную часть справочника: совпадения распределены по многим блокам.
[Машинный протокол](results/clickhouse-indexes.json). Повторение с экспортированными
переменными ClickHouse:

```sh
PYTHONPATH=backend/src backend/.venv/bin/python etl/analytics/benchmark_queries.py --output /tmp/clickhouse-benchmark.json
```

Подготовленный дорожный слой содержит 4 305 460 линий из всех 17 393 384 направленных
рёбер. Для окна `(38, 54, 43, 57)`, zoom 7, предыдущая проверка показала 29 765 объектов
вместо 64 779, ответ 6,77 МБ вместо 12,95 МБ и медиану HTTP 0,70 с по трём запросам.
[Протокол дорожного слоя](results/road-render-performance.json). Меньший ответ сокращает
работу клиента, но не устраняет стоимость отрисовки больших наборов геометрии.

## Как сохраняются числа и задания?

Граф и матрицы передаются через Arrow: `Float32`, `Float64`, большие идентификаторы
и бесконечное время недостижимого маршрута сохраняют значения. Вставки типизированных
документов и заданий также используют Arrow. Вложенные объекты хранятся именованными
кортежами; необязательный сложный объект — массивом из нуля или одного элемента.
Это различает отсутствие объекта и пустой список внутри него.

Задания используют `ReplacingMergeTree(updated)`. Вставляется новая версия целого
состояния; чтение с `FINAL` выбирает актуальную. Прогресс рабочего цикла держится в
памяти, завершение и контрольные точки сохраняются в БД. После рестарта незавершённые
анализы помечаются прерванными и могут продолжиться с контрольной точки. Это локальная
очередь одного API-процесса, распределённого захвата задач несколькими серверами нет.

Численные кэши `scenario-cache` и CSR в `scenario-results` остаются на диске: повторное
вычисление кратчайших путей существенно дороже их загрузки. Пространство ключей задаётся
версией снимка из `atlas_metadata`; проверок существования исходных файлов нет.
Кэши можно пересоздать из БД. Они не заменяют исходные таблицы.

## Как проверить перенос?

Проверены SHA-256 файлов, числа строк и NULL всех 50 таблиц. Все 6 990 556 узлов и
17 393 384 рёбер сопоставлены с исходниками, включая дубли и веса. Для региональной
матрицы совпали 454 680 записей, в том числе 47 733 бесконечных времени.

API запущен без исходных файлов в рабочих каталогах. Ответы атласа совпали с файловой
версией, повторный сценарий добавления связи дал идентичные индекс, эффекты по пунктам
и денежную оценку. На уже подготовленном кэше вычисление заняло 0,042 с в одном запуске;
это не оценка полного пересчёта и не задержка интерфейса.

124 проверенных исходных файла, 2 366 682 834 байта, удалены; список сохранён в
`plexus_atlas.migrated_sources`. Необработанные архивы и документы источников сохраняются
отдельно: они не были автоматически превращены в рабочие таблицы. Файловые репозитории
в коде используются только импортом и тестовыми фикстурами; в `main.py` они не подключены.
DuckDB отсутствует в рабочих зависимостях backend и оставлен в группе `dev` для ETL.

## Как запустить и обновить снимок?

См. [инструкцию запуска](running.md). Данные живут в именованном Docker volume
`plexus-analytics_plexus_analytics`; удаление этого volume удаляет базу.
Обычный `docker compose down` volume сохраняет. Резервное копирование volume
или таблиц ClickHouse должно быть частью эксплуатации; копии на другом носителе
в этой локальной проверке не создавались.

Для первоначальной загрузки восстановленного исходного набора:

```sh
set -a
source .env.analytics
set +a
backend/.venv/bin/python etl/analytics/import_data.py
backend/.venv/bin/python etl/analytics/import_atlas.py
PYTHONPATH=backend/src backend/.venv/bin/python etl/analytics/build_roads.py
PYTHONPATH=backend/src backend/.venv/bin/python etl/analytics/build_atlas_tables.py
backend/.venv/bin/python etl/analytics/index_runtime.py
backend/.venv/bin/python etl/analytics/index_corridors.py
backend/.venv/bin/python etl/analytics/import_state.py
```

Импорт выполняется отдельно от запросов API. Промежуточные таблицы заменяют рабочие
после проверок. Для согласованной замены всех таблиц требуется остановить расчёты,
импортировать весь снимок и перезапустить API; общей транзакции на все базы здесь нет.
Фактическая схема: [snapshot-schema.sql](../infra/clickhouse/snapshot-schema.sql).
