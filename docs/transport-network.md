# Ж/д и авиасвязи в атласе

Обновление 10.11.2026 добавляет 34 096 записей в API и интерфейс: 33 957 модельных направленных пар городов, 135 записей расписания ЮВТ Аэро и четыре направления Железных дорог Якутии. С прежними данными в атласе 46 487 записей; ж/д представлены в 76 регионах, авиа — в 67 из 82 регионов продукта. Это покрытие источниками, а не проверка действующего сообщения во всех населённых пунктах.

[«Точно»](https://tochno.st/datasets/intercity_connectivity) описывает пары городов и модельное время. В интерфейсе эти записи имеют метку «Модельная связь». Они не подтверждают прямой поезд или рейс. Их линии включаются отдельно, чтобы плотная матрица связей не закрывала карту.

Из [расписания ЮВТ Аэро](https://www.uvtaero.ru/raspisanie) импортированы записи с периодом, включающим 10 ноября 2026 года, днями недели и местным временем для каждого аэропорта. Четыре записи Казань — Нальчик и обратно с противоречащим временем исключены. Направления за пределами сопоставленных городов и записи, исходящие из городов вне 82 регионов атласа, не импортированы; причины записаны в манифесте. Один маршрут может иметь несколько записей для разных дней недели. Это не число уникальных направлений.

[ЖДЯ](https://rw-y.ru/passengers/schedule/traffic/?special=Y) публикует цепочки Нижний Бестях — Тында и Нижний Бестях — Благовещенск в обе стороны. Источник не указывает период действия, дни движения и часовой пояс. Эти поля остались неизвестными; время поездки не вычислялось из часов прибытия.

У всех новых записей поле сезона пустое: даты расписания не превращаются в утверждение о ежегодной сезонности. API по умолчанию сохраняет строгий сезонный фильтр. Параметр `include_unknown=true` дополнительно возвращает связи без календаря; интерфейс использует его и поясняет это в легенде и карточках. Сводка выбранного региона показывает все записи источников. Сезонные счётчики продолжают учитывать только известный сезон.

Линии соединяют центры населённых пунктов по имеющимся координатам. Это схема связности, не геометрия железных дорог и не точное положение аэропортов. Пункты без однозначных координат не добавляются по предположению. На карте отображаются связи выбранного региона; встречные линии с одинаковыми координатами объединены визуально, записи API сохраняются.

## Хранение и повторная сборка

`frontend/atlas/public/network-links.json` — отдельный дополнительный набор. API объединяет его с исходным `atlas.json`; исходные записи не переписываются. Отсутствие дополнительного файла сохраняет прежнее поведение. Ошибка чтения существующего файла возвращает ошибку данных.

`network-links.manifest.json` содержит SHA-256, счётчики и исключённые записи. Скрипты `etl/import_uvt_schedule.py` и `etl/import_yakutia_schedule.py` воспроизводят извлечение из сохранённых HTML. `etl/export_network_links.py` объединяет их с `stg_intercity` из `data/casechamp.duckdb`.

Индексы Hansen и подготовленные матрицы не пересчитаны. Модельные ж/д и авиа уже использовались расчётным кодом; новые расписания добавлены в каталог связей, но пока не включены в расчётные графы. Остальные найденные сайты без извлечённых маршрутов остаются источниками для дальнейшего сбора.
