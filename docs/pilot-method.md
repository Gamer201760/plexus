# Как оценить изменение сообщения в Тыве

> Пилот сравнивает условные поездки жителей к выбранным центрам по одному правилу.
> Увеличение частоты может дать нулевой эффект, если дорожная альтернатива остаётся быстрее.

**Читайте, если** проверяете расчёт или воспроизводите опыт · **Связано:** [Источники пилота](pilot-sources.md)

---

## Какие поездки сопоставимы?

Кунгуртуг и Тоора-Хем сравниваются до Кызыла в одном сезоне и при одинаковых допущениях.
Поездка Сыстыг-Хем → Тоора-Хем рассматривается отдельно: её центр назначения другой.
Показатели пилота образуют систему: достижимость, модельное время, движение с накладными,
ожидание, маршрут и изменение времени относительно базы. Меньшее время означает большую
доступность в этой модели. Отсутствие пути не получает числового места в рейтинге.

## Как получается время?

Для маршрута складываются движение с накладными и ожидания на линиях. Модель выбирает
минимальную сумму по рассматриваемому графу. Частотное ожидание равно `84 / f` часов,
где `f` — рейсы в неделю. Это допущение равных интервалов, случайного момента потребности
и независимых пересадок. Планирование поездки под рейс, согласованные пересадки и отмены
не моделируются. Вариант без ожидания — оптимистическая граница.

Неизвестная частота остаётся неизвестной в исходной записи. Если для расчёта задано
1 отправление в неделю, результат и JSON сохраняют это как допущение. Потенциальные
альтернативы с неизвестной частотой проверяются по нижней границе с нулевым ожиданием:
если они могут улучшить найденный результат, API возвращает предупреждение.

У исходной авиационной линии указаны вторник и четверг. Для интервалов 48 и 120 часов
ожидание случайной потребности составляет `(48² + 120²) / (2 × 168) = 49,714` часа.
Равномерная модель двух рейсов даёт 42 часа. Эта чувствительность показана отдельно;
основная база и варианты сохраняют одну частотную модель. Полное расписание цепочки
поездок не рассчитывается.

## Чем проверяется расчёт?

Артефакт содержит 7 пунктов, 19 рёбер и 3 пары. Дорожные пути получены из сибирского
снимка Geofabrik; список OSM-way каждого пути сохранён в [манифесте](results/tuva-provenance.json).
Проверка 133 way, использованных в путях, не выявила тегов `access`, `vehicle`,
`motor_vehicle` или `motorcar` со значениями `no`/`private`. Это проверка тегов, а не полевых условий.
Сыстыг-Хем не имеет привязки к большой дорожной компоненте в пределах 5 км.
Его редактируемые сезонные связи не спрятаны внутри дорожной матрицы.

[Протокол расчёта](results/pilot-validation.json) сравнивает 24 результата с независимым
Флойдом—Уоршеллом, проверяет повторяемость и неизменность файла. Контрольные примеры
в `tests/test_transport_model.py` проверяют равенство исходного и сжатого графа по сезонам
и при удалении связи. Backend-тесты проверяют настоящий артефакт через HTTP; Playwright
проверяет карту, редактирование, расчёт, экспорт и сброс на desktop.

```bash
uv run python -m unittest discover -s tests
PYTHONPATH=backend/src uv run python etl/validate_pilot.py
cd backend
uv run pytest tests/unit tests/integration
```

[HTTP-замер](results/pilot-http-benchmark.json) относится к 200 последовательным запросам
через loopback после загрузки артефакта. Он не характеризует внешнюю сеть, конкурентную
нагрузку или время первого старта. Отдельная локальная проверка расчёта также исключает HTTP.

## Как воспроизвести опыт через API?

`GET /api/v1/pilots/tuva` возвращает источники, параметры, пары и версии.
`POST /api/v1/pilots/tuva/evaluate` принимает сезон, обе версии и изменения рёбер.
Для авиационной линии идентификатор `manual:0`; частоты 4 и 7 дают варианты таблицы.
Зимняя связь имеет ID `manual:5`, летняя водная `manual:6`.

Частота пользовательского ввода — целое число от 1 до 28. Исходные значения за пределами
диапазона сохраняются без округления и отключают редактирование. Устаревшая версия
возвращает 409, некорректный ввод — 422, отсутствующий или повреждённый артефакт — 503.
Схема публикуется в OpenAPI. Экспорт JSON содержит сам граф, условия и результат;
CSV — сравнение с единицами, версиями и параметрами последнего выполненного расчёта.
