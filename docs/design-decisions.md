| Один язык (русский) и одна светлая тема | Половина строк без перевода, недопроверенная тёмная палитра | Правило `single-theme`, тест словарей | Возврат второй темы потребует семантического слоя заново |

| Камера обновляется максимум раз за requestAnimationFrame; состояние React фиксируется после отпускания или 180 мс без колеса. Перелёт длится 260 мс и прерывается из текущей позиции | Ввод запускал повторные рендеры и длинные непрерываемые перелёты | `use-map-camera.ts`, `map-interaction.spec.ts` | Клавиатурный зум и reduced motion работают без перелёта |
| Во время колеса, перетаскивания, щипка и перелёта двигается HTML-обёртка обоих SVG (`data-map-stage`, постоянный `will-change: transform`) как готовая картинка. Группа SVG, отсечение контуров и толщина линий меняются только при фиксации вида. Если масштаб внутри жеста вырос в 2,5 раза или упал до 0,4 от последней фиксации, вид фиксируется без завершения жеста | `transform` на группе внутри SVG не выносится в композитный слой: каждый кадр жеста заново растеризовал карту. Замер Chromium, CPU ×4, 140 событий тачпада: растр 6,0 с до, 0,07 с после | `map-painter.ts`, `map-motion.ts` (`viewShift`), `map-regression.spec.ts` | При приближении картинка размыта и линии толще до фиксации; дальние области за запасом отсечения появляются только после фиксации |
| Показаны контуры, пересекающие окно с запасом в один экран с каждой стороны, а SVG рисует за своими границами (`overflow: visible`). Подсветка находится в отдельном SVG со своим слоем; попадание проверяется по кэшированному Path2D | При отдалении и перетаскивании без запаса края сцены оставались пустыми; смена подсветки перерисовывала соседние регионы | `map-painter.ts`, нагрузочные измерения | Слой сцены и слой подсветки постоянно занимают память видеокарты |
| Материковая часть для фокуса определяется по площади крупнейшего полигона из исходного контура. Выбор не зависит от запаздывающего ответа карточки региона | Острова Архангельской области сдвигали центр камеры, предыдущая карточка могла запустить неверный перелёт | `map-shapes.test.ts`, `map-regression.spec.ts` | Географические координаты островов сохранены; для островного региона фокусируется крупнейший остров |
| Перетаскивание разрешено при масштабе 1; ограничитель оставляет не меньше 15% рамки карты в окне | На исходном масштабе обе границы ограничения совпадали и блокировали сдвиг | `map-gesture.test.ts`, браузерная проверка перетаскивания сразу после открытия | Это ограничение рамки, а не фактической площади суши |
| Регионы на карте не получают фокус с клавиатуры; выбор с клавиатуры идёт через поиск, рейтинг и список регионов | 83 лишние остановки табуляции | `// biome-ignore` с причиной в `russia-map.tsx` | Карта без мыши служит иллюстрацией |
| Знак хранится как контуры (`docs/brand/*.svg`, `shared/ui/brand/mark-paths.ts`), кольца посчитаны смещением контура букв | Знак зависит от установленного шрифта | Контуры в `docs/brand/` | Изменение параметров знака требует повторного экспорта |
| Шкала карты: естественные разрывы (Fisher–Jenks) по логарифму значений, каждый порог округлён до самого круглого числа между классами, ноль отдельным классом | Квантили сливали Якутию (38 связей) и Красноярский край (115) в один цвет | `tests/features/map-explorer/scale.test.ts` | Пороги меняются вместе с данными |
| Показатель и сезон карты хранятся в адресе (`?metric=&season=&region=`) | Перезагрузка или ссылка теряет выбранный вид | `use-explorer-params.ts` | Значения по умолчанию в адрес не пишутся |
| Колесо обрабатывается нативным обработчиком с `passive: false`; масштаб зависит от величины и единиц delta. Горизонтальный свайп сдвигает карту, два указателя задают pinch | Зум карты одновременно увеличивал страницу, горизонтальное движение уменьшало масштаб | `map-gesture.ts`, модульные и браузерные тесты | Browser zoom доступен вне карты; Safari gesture events отменяются, физический Safari не проверен |
| Координаты курсора хранятся в ref, карточка двигается через transform. React получает только смену региона | Каждый пиксель движения пересчитывал панель и шкалу | `use-map-hover.ts`, memo для панели, легенды и тулбара | Во время жеста подсказка скрыта |
| До масштаба 2 используется `path_low`, выше исходный `path`. Уровень выбирается только при фиксации и меняется только у контуров, видимых в окне; контуры в запасе получают нужный уровень при следующей фиксации. Экспорт выполняется mapshaper, параметры описаны в `api.md` | Переключение всех 83 контуров на каждой паузе колеса давало до 1 177 замен `d` за один сеанс зума, теперь 51 | `prepare-map-detail.mjs`, тест охвата геометрии, `map-regression.spec.ts` | Мелкие острова могут исчезать в общем виде; контур за окном может временно иметь другой уровень детализации |
| Верхняя навигация переключает страницы без View Transition; остальные ссылки сохраняют прежнее поведение | Захват всего экрана задерживал частые переключения и блокировал взаимодействие | Браузерный тест быстрой навигации, замер кадров | Осознанное исключение из общего правила анимации переходов для часто используемых вкладок |
| Таблица регионов растёт вместе со страницей; внутри остаётся только горизонтальная прокрутка при нехватке ширины | Вертикальный скролл попадал то в таблицу, то в документ | Браузерный тест прокрутки из строки таблицы | Заголовок таблицы не закреплён относительно окна; 82 строки остаются в DOM |

| Главная открывается по `/`, рабочая карта по `/map`; интерфейс собран из React-компонентов | Статический макет не подменяет рабочие экраны и их API | Маршруты, `home-intro`, `map-explorer`, браузерные сценарии | На главной нет шапки и навигации: единственный путь дальше это кнопки «Открыть атлас» и «Как мы считаем» |
| Контуры, буквы и иконки унаследованы из утверждённых макетов; цвета и размеры используют общие токены | Разная графика на главной и внутренних экранах | `brand`, `design-glyphs.json`, токены типографики и hero | Макеты служат визуальным образцом; HTML не загружается в приложение |
| Главная в две колонки: слева лого, заголовок, текст и кнопки по центру между краем страницы и картой, справа карта без фона, суша в фирменном голубом с мягкой тенью. Карта главной строится из `GET /api/v1/links`: точки это концы ручных связей, тур по очереди показывает до десяти узлов с сетью не меньше 8 связей и размахом от 60 единиц карты, совпадающие станции склеены; линии рисуются один раз от узла до станций, волны проходят дважды и гаснут | Постоянные анимации и масштаб камеры давали лаги, обрезанную карту и линии, не доходящие до точек | `features/home-intro/atlas-scene.ts`, e2e главной | Тур останавливается под указателем; при reduced motion показан первый узел без смены |
| При выборе региона на `/map` от его границы расходятся две волны за 0,56 с и удаляются; они живут в слое наведения и стартуют только после остановки камеры | Постоянные кольца и волны во время перелёта перерисовывали всю карту | `entities/region/russia-map/map-ripple.ts`, `map-painter.ts` | Волна это растянутая копия упрощённого контура, у вогнутых регионов форма неточная |
| Транспортный состав таблицы собирается из существующего эндпоинта региона, по шесть запросов одновременно, с общим кешем | Новые поля экрана требуют незапланированного изменения API | `composition.queries.ts`, реальные ответы `links_by_mode` | Холодное открытие требует отдельного запроса для каждого региона со связями; на проверенном наборе их 63 |
| Сезон хранится в URL и передаётся в ссылки таблицы, навигации и поиска | Переход сбрасывает лето на зиму | `useSeason`, DOM RouterProvider, e2e быстрого перехода | Неизвестный сезон нормализуется в зиму; режим «Все» не входит в новые элементы управления |
| Отложенный перевод фокуса на заголовок не прерывает ввод в поле | Поиск закрывается при быстром вводе сразу после перехода | `useRouteFocus`, e2e перехода и поиска | При обычной навигации фокус по-прежнему переходит в основной контент |
| Таблица регионов использует горизонтальный ScrollArea и прокрутку документа по вертикали | Колесо над строкой перестаёт двигать страницу | `DataTable.scrollOrientation`, e2e прокрутки | Состав связей остаётся таблицей, без отдельной вертикальной области прокрутки |
| На `/map` возвращён большой экран карты из версии до переноса макетов; выбор региона приближает его материковый контур | Новый экран карты не соответствовал ожидаемому основному сценарию | Запрос пользователя, прежний `MapExplorer`, e2e карты | Главная с анимацией остаётся на `/`; CTA открывает `/map` со всеми сезонами |
| Каталог показывает одну из четырёх тем и запоминает выбор при переходах | Пользователь повторно ищет открытую тему | `source-catalog`, общие Tabs и Disclosure | Память действует в текущем запуске приложения; URL темы имеет приоритет |
| Смена темы указателем даёт прерываемое появление через opacity; клавиатура и reduced motion переключают сразу | Быстрые действия накапливают анимации или откладывают фокус | `useContentFade`, тесты Tabs и браузерный сценарий | Анимация не меняет геометрию панели |
| Календарь показывает отдельные маршруты одного сезона, сравнение совмещает месяц и день двух лет | Сводные строки удваивают маршруты, а прошлый год выпадает за шкалу | `calendar-time`, unit-тесты, реальные winter-roads | Сейчас API содержит календарь Югры; он доступен только в её карточке |
| Конец полосы берётся из даты закрытия либо отчёта; неизвестное закрытие явно подписано | Дата отчёта воспринимается как подтверждённое закрытие | `calendar-row`, раскрытие дат и имени файла источника | Интервал не доказывает непрерывную работу; API не даёт URL PDF и наблюдений МЧС, эти блоки не добавлены |
| Матрица методики вычисляет иллюстрацию с периодом полураспада из API; формула использует MathML | Пример выдаётся за рассчитанный индекс регионов | `accessibility-method`, явная подпись иллюстрации и статус API | Региональный индекс по-прежнему не подключён; существующие населённые пункты и финансовые показатели сохранены в раскрываемом блоке карточки |

Синхронное обновление сезона использует DOM-вариант `RouterProvider`, который подключает `flushSync`: [документация React Router](https://reactrouter.com/7.18.5/api/data-routers/RouterProvider). Это удерживает адрес ссылки и видимый сезон в одном состоянии при быстром клике.



## Правки взаимодействия после просмотра, 2026-11-08

| Решение | Причина | Проверка | Предел |
| --- | --- | --- | --- |
| Подчёркивание Tabs рисуется границей выбранной вкладки | Перемещение отдельной полосы через ряд вкладок воспринималось как лишняя длинная линия | Переключение удалённых вкладок без clip-path-анимации индикатора | Появление содержимого сохранено; клавиатура переключает сразу |
| Матрица меняет выбранный пример при наведении, фокусе и клике | Для чтения каждого примера приходилось нажимать клетку | E2e наведения и фокуса с проверкой подписи | Числа остаются иллюстрацией формулы |
| Таблица населённых пунктов передаёт вертикальное колесо документу | При `overscroll-behavior: contain` страница оставалась на 4095 px после колеса, хотя конец был ниже | E2e доходит до конца страницы через область таблицы | Горизонтальная прокрутка таблицы сохранена |
| При выборе региона панель карты показывает его связи населённых пунктов | Рейтинг России оставался рядом с выбранным регионом и смешивал масштабы | E2e сверяет число строк и конечные пункты с ответом существующего API | Без выбора региона остаётся общероссийский обзор; фильтр сезона применяется к списку |
| Список связей общий для карты и карточки региона | Две версии строки могли расходиться в названиях и ссылках на источники | Компонент `entities/link/link-list`, существующий `useRegionLinks` | Карточка по-прежнему отдельно выделяет связи одного сезона; карта показывает все записи выбранного сезона |

## Национальный расчёт и интерактивный опыт

| Правило | Какой сбой предотвращает | Чем закреплено | Остаточный предел |
| --- | --- | --- | --- |
| Palma делит население пункта на границах 40% и 90%; исключает пропуски и нулевые веса | Крупный пункт целиком попадает в хвост и искажает отношение | `tests/test_transport_model.py`, равные значения с весами 45/45/10 дают 0,25 | При нулевом нижнем хвосте отношение бесконечно; при нулевых обоих — не определено |
| Ожидание регулярной линии равно 84 / частота в неделю, без ограничения | Рейсы 1, 2 и 3 раза в неделю получают одинаковое время | Контроль времён 84/42/28 ч в `tests/test_transport_model.py` | Допущение случайного момента потребности и равных интервалов; не расписание |
| Сезонные рёбра фильтруются до поиска; неопределённый режим исключается | Летний маршрут проходит по зимнику или неизвестной переправе | Контрольный граф: летом 5 ч, зимой 2 ч | Неполные теги OSM не устанавливают фактическое открытие |
| Национальная базовая сеть `road` исключает магистральные ЖД/авиа; летняя и зимняя сети их допускают | Надпись «только дороги» описывает смешанный маршрут | Раздельное построение матрицы в `etl/access_russia.py` | Магистральные накладные — допущение; частоты магистральных рейсов неизвестны |
| Хранятся все конечные времена без отсечения 72 ч | Дальние цели теряются в Harris, хотя их вклад ещё существенен | Фильтр конечных значений в `etl/access_russia.py` | Полный пересчёт обязателен перед публикацией национальных результатов |
| Загрузка SQL и замена расчётных таблиц атомарны | Неудачный расчёт оставляет частично обновлённую базу | Транзакции DuckDB в `etl/load.py` и `etl/access_russia.py` | Экспорт и национальный прогон требуют отдельной проверки |

## Сценарий «новый маршрут» для национального индекса, 10.11.2026

Индекс пересчитывается точно без повторного прогона тяжёлого пайплайна. Из DuckDB
экспортируются матрицы времён: дорога от каждого н.п. до каждого из 180 городов,
лучшие времена и замкнутая матрица город-город (etl/export_scenario_matrices.py,
data/scenario_ru, npy с mmap). Новая связь получает вес «время + 84/частота +
накладные» как у магистральных плеч; городская матрица замыкается Флойдом-Уоршеллом
(180×180), затем обновляются только столбцы улучшенных городов, и Hansen
пересчитывается по изменённым вкладам. Проверки: замыкание матриц 0.0000 ч,
региональные индексы расходятся с опубликованными не более 0.6%
(data/scenario_ru/manifest.json, published_reference).

numpy допущен в domain/usecase как чистая вычислительная библиотека: формула
Hansen на 155 412 × 180 значениях не выполнима на чистом Python за время ответа
API. Разрешение закреплено в PURE_LIBRARIES архитектурного теста.

У трёх городов федерального значения нет точки населённого пункта, поэтому их
строки городской матрицы восстановлены из магистральных плеч и дорожных времён
якорных точек соседних городов с последующим замыканием; точность покрыта той же
проверкой замыкания. Сезонность дорог локального графа аппроксимирована по
is_seasonal (ferry → unknown, сезонные → winter), допущение
seasonal_roads_approximated_from_is_seasonal записано в манифест артефакта.

## Локальный агент карты, 10 ноября 2026

Pydantic AI находится в адаптере за портом `ChatProvider`; domain/usecase не зависят
от SDK. Codex SDK проверяет текущую авторизацию, а Responses-провайдер Pydantic AI
обращается к Codex backend. Подписка не превращается в публичный proxy API.
Инструменты используют существующие запросы атласа, без shell и произвольного чтения файлов.

Браузер читает NDJSON через типизированный openapi-fetch внутри TanStack mutation.
Повторная попытка запускается только пользователем, чтобы не дублировать расходы после обрыва.
Async-генераторы закрываются явно при отмене. Частичный ответ остаётся видимым, но не
отправляется как завершённый ответ в историю. Действия инструмента показывают начало вызова,
а не гарантируют его успешное завершение. История не сохраняется на диск.

Чат наследует композицию rwb и визуальные токены Plexus. Streaming не анимирует каждый
фрагмент; Markdown безопасно отображается без HTML и внешних изображений. Вкладка сводки
сохраняет существующие данные карты. Документация и атрибуция: [chat.md](chat.md).


### Таблицы и графики в потоке ответа

Инструменты чата передают строки атласа отдельными событиями `table`. Команда
`show_chart` принимает только идентификатор существующей таблицы и её колонки;
значения для столбцов берутся из сохранённого результата. Таблицы изолированы
между запросами. Пропуски остаются пропусками, покрытие Hansen видно в таблице.
Нормализация текста сохраняет код, списки и оговорки о качестве данных, а источники
складывает под раскрытие. Текст продолжает поступать дельтами без ожидания полного ответа.


### Управление камерой из чата

Агент передаёт проверенные идентификаторы регионов вместо произвольных координат.
Один вызов фокусирует всю группу, чтобы карта не перелетала между её участниками.
Команда исполняется один раз; ручной выбор региона заменяет фокус агента. Слой
выделения меняется фильтром MapLibre, геометрия и экземпляр карты не пересоздаются.
Перелёт камеры длится900мс (`--dur-map`): это пространственный переход через большие
расстояния, для которого разрешено исключение из300мс бюджета обычных контролов.
Используется встроенная траектория `fitBounds`/`flyTo` с curve1.25, без вращения и
наклона. Зум на один шаг сохраняет260мс. Новый переход отменяет предыдущий;
перетаскивание и колесо остаются доступны. Reduced motion отключает перемещение камеры.

Математические выражения рендерятся через MathML, чтобы формулы оставались доступны
считывателям экрана и не требовали внешних шрифтов. Документация библиотек:
[remark-math](https://github.com/remarkjs/remark-math),
[MapLibre fitBounds](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/FitBoundsOptions/).


## Единый источник дорожного сценария

Для локального графа используется восстановленная пара DuckDB/Parquet data-20261107.
`SnapshotAtlasRepository` заменяет индексный источник для карты и сравнений; новые проектные
расчёты используют ту же модель, а не базу из более поздних JSON. Каталоги и геометрия границ
сохраняются. Название «Базовая сеть» отражает факт: исходный road включает магистральные
ЖД/авиасвязи. Не добавляем отсутствующие в снимке ограничения сезонов дорог или новое ожидание
84ч. Проверка воспроизводимости обязательна перед первым сценарием региона/сезона.

SciPy/NumPy изолированы в вычислительном адаптере, DuckDB открыт read-only. `Any` в этом
адаптере ограничен массивами без полных stubs и строками научных драйверов; порты и HTTP
имеют явные dataclass DTO. Последовательный worker ограничивает пиковую память. Результат
и проверенный baseline сохраняются отдельно от источников. Кеш базы учитывает размер/mtime
исходных файлов и версию алгоритма; изменение алгоритма требует новой версии ключа.
Полный поиск применяется ко всем180 рынкам по национальному графу. Дубликаты рёбер выбираются
по минимуму, включая после изменения скорости/закрытия. Для отображения выбираются целые
OSM ways с приоритетом класса; прореживание не влияет на маршрутизацию.

Дорожный слой и начальная камера запускаются на `style.load`: загрузка внешних растровых
тайлов не должна блокировать локальный граф. Выбор/результат сценария вынесены в отдельную
вкладку существующей панели; агент запускает тот же use case, панель получает общий журнал.


### Предрасчёт и добавление связи, 10 ноября 2026

Для базовой сети подготовлены расстояния населённых пунктов до 180 рынков, межрыночная
матрица, исходные Hansen и фиксированная нормировка. Проверены все 84 записи регионов
снимка. Данные сохраняются атомарно в NPZ без pickle и загружаются при старте.

Одна новая положительная двусторонняя связь (a,b,w) меняет расстояния по формуле
`min(d(i,j), d(i,a)+w+d(b,j), d(i,b)+w+d(a,j))`. Обновляются затронутые расстояния,
затем межрыночные переходы и Hansen. Поиск по всему дорожному графу для подготовленных
концов не повторяется. Это точный алгоритм для одной добавленной связи, с обычной
погрешностью float32; он не применяется к закрытию дороги или пакету взаимодействующих связей.
Для новых концов кешируются проекции одного поиска на все точки и рынки.

Денежный результат относится к заданной пользователем паре отправление–рынок:
сэкономленные часы × поездки в год × рубли в час. Эксплуатационные затраты вычитаются;
простая окупаемость показывается при положительной чистой экономии и капитальных затратах.
Это условная стоимость времени, не доход бюджета, выручка или прирост ВРП.

Карта удерживает последнюю успешную геометрию во время нового запроса и ошибки. Обновление
статуса сценария не загружает геометрию повторно. Оранжевый слой показывает граф снимка,
синий — границы регионов, фиолетовый пунктир — гипотетическую связь. Серые дороги подложки
могут отличаться по дате, геометрии и охвату. Слой графа не является слоем автобусов.


## Детализация дорожного расчёта для автоматического анализа

`GraphRouting.calculate_details` возвращает тот же региональный результат, что и
`calculate`, вместе с нормированным Hansen, населением и достижимостью рынков
для каждого исходного населённого пункта. Пункты без привязки сохраняются с нулём
и отсутствием пути; они продолжают входить в знаменатель регионального показателя.
Достижимость вычисляется по конечности времени пути, отдельно от Hansen: малое
значение экспоненты не означает отсутствие пути.

`compare_access` сопоставляет пункты по идентификаторам, проверяет неизменность
населения и считает только вновь изолированных жителей. Порог изменения индекса:
`max(1e-6, abs(before) * 1e-7)`. Потеря достижимости учитывается независимо от порога.
Рейтинги, отбор кандидатов, фоновые порции и интерфейс используют эту детализацию.
Метод и пределы проверки: [автоматический анализ дорог](road-analysis.md).

## Визуализация закрытия в чате

Инструмент закрытия именованного участка отправляет отдельное событие `calculation`
с геометрией и идентификаторами заданий. Карточка появляется независимо от текста модели,
опрашивает каждое задание и показывает серверный прогресс и результат каждого региона.
Схема дороги пульсирует только пока есть незавершённый расчёт; это индикатор ожидания,
а не анимация распространения транспортного эффекта. При ошибке доступны повторное чтение
и явное сообщение. Завершённые задания перестают опрашиваться карточкой.

Карта приближается к геометрии при первом показе карточки и по кнопке пользователя.
Обновления прогресса не меняют камеру. Повторное управление с клавиатуры и настройка
уменьшения движения отключают перелёт. Событие относится к текущему сообщению;
старые сообщения без такого события не восстанавливают геометрию автоматически.

## Подготовленный дорожный слой в ClickHouse

Полные расчётные рёбра и геометрия отображения имеют разные задачи. Отдельный порт
`RoadViewSource` позволяет отдавать заранее соединённые линии из ClickHouse, сохраняя
исходные массивы для расчёта сценариев. Отбор использует границы линии и класс дороги;
внутренние узлы не удаляются. Клиент сохраняет геометрию при смене выделения и выбирает
дорогу по стабильному OSM ID. Решение, обновление данных и ограничения измерения:
[аналитическое хранилище](clickhouse.md).

## Рейтинг и комментарий внутри чата

Событие `analysis` передаёт реальное задание в сообщение. Клиент опрашивает его через
общий кэш запросов и показывает только проверенные результаты. Ожидание расчёта не
удерживает соединение с моделью. Завершение порции запускает отдельный запрос
комментария, где сервер подставляет сохранённые результаты и не регистрирует инструменты.
Обычные ответы и комментарии выполняются последовательно через одну очередь запросов.
Это сохраняет возможность писать в чат во время расчёта и предотвращает конфликт
двух запросов с единственным исполнителем модели. Повторный опрос готовой порции
не запускает новый комментарий; ошибка LLM не скрывает вычисленные значения.

## Привязка к дорогам и извлечение подъездов

При сборке графа населённый пункт выбирает узел автомобильной дороги. Вершины
`route=ferry` исключены из кандидатов привязки: близкий речной маршрут мог
перехватить точку, после чего автомобильный сценарий удалял его рёбра и терял
путь к рынкам. Порог привязки 5 км сохранён. Переправы остаются рёбрами сети
и подчиняются прежним правилам сезонности.

Сборщик включает `highway=service` с разрешённым автомобильным доступом,
исключая частные и целевые проезды, парковочные ряды, въезды на участки,
аварийные проезды и неразобранные условные ограничения. Приоритет тегов:
`motorcar`, `motor_vehicle`, `vehicle`, `access`. Отсутствующий тег доступа
трактуется как разрешение; это допущение полноты OSM. Модельная скорость
подъезда — 15 км/ч с прежней поправкой на поверхность. Соединения возникают
только по общим OSM node ID. Назначение тега описано в
[документации OSM](https://wiki.openstreetmap.org/wiki/Tag:highway%3Dservice).

На 10.11.2026 эти изменения проверены на контрольном OSM-файле и локальном
графе. Полная сборка из свежих исходников и пересчёт опубликованного индекса
ещё не завершены. Правка сборщика сама по себе не обновляет готовые артефакты.

| Типизированная вставка через Arrow | Округление Float64 при текстовом разборе, потеря Inf в матрицах | Сравнение всех узлов и рёбер; интеграционный тест матрицы | Память для подробного графа всё ещё нужна |

| Числа восстанавливаются согласно типу DTO | JSON-ответ БД может представить Float64 `95.0` как `95`, меняя хеш геометрии | Тест стабильных типов и проверка совместимости всех сохранённых анализов | Хеш привязан к версии снимка |
| Первичный ключ начинается с условий реального запроса; отдельные проекции для OSM ID и номера дороги | Чтение всей таблицы при выборе дороги или региона | EXPLAIN и протокол объёма чтения | Триграммный индекс мало помогает коротким и частым строкам |
| Состояние задания записывается одной версией и читается с FINAL | Чтение нескольких версий одного результата | `ReplacingMergeTree(updated)`, контрольные точки | Очередь рассчитана на один API-процесс |

## История разговоров в браузере

Каждый разговор хранится отдельной версионированной записью браузерного хранилища.
Это сохраняет переписку без нового серверного API и не удаляет другие разговоры при
сохранении текущего. Активный ID хранится отдельно. Запись изменённых разговоров
планируется на свободное время браузера и выполняется также при уходе со страницы.
При ошибке записи интерфейс сообщает о ней; автоматического удаления старых чатов нет.
Повреждённая запись не мешает загрузить остальные и не перезаписывается пустой историей.

Поток ответа привязан к ID разговора, а не к открытой панели. Переключение не меняет
получателя ответа. Команды карты выполняются только для активного разговора, а старые
карточки расчётов не запускают автоматический перелёт при повторном открытии. Текст и
ревизия комментария к анализу входят в сообщение: готовый комментарий восстанавливается
без нового вызова модели, прерванный доступен для явного повтора.

## Версия графа и расчётная модель

Расчётный движок читает `model_version` из метаданных снимка ClickHouse.
Для `hansen-frequency-v2` автомобильная база включает только всесезонные
дорожные рёбра. Летний и зимний автомобильные сценарии добавляют разрешённые
сезонные дороги и ручные автомобильные связи. ЖД и авиация входят в смешанные
сценарии; при неизвестной частоте магистрального сообщения применяется
принятое в национальном расчёте ожидание 84 часа. Поездка рынка к самому себе
имеет нулевое время. Пути длиннее 72 часов сохраняются в матрице.

Старый снимок без этой версии продолжает использовать свою исходную формулу.
Так загрузка нового кода не меняет смысл ещё не пересчитанных таблиц.
Идентификатор нового графа зависит от ревизии данных; кэш расчёта другого
снимка не используется. Завершённые задания прежних версий остаются в истории.
Перед заменой таблиц региональные базовые расчёты API сверяются с новой
матрицей и индексами. Во время обмена таблиц API останавливается, поскольку
несколько обменов ClickHouse не составляют общую транзакцию.

Национальный поиск маршрутов использует симметричную CSR-матрицу: минимальное
время каждого ребра уже записано в обе стороны. Поэтому обход SciPy с
`directed=True` сохраняет неориентированные пути и не строит вторую копию
транспонированной сети. Независимые поиски от городов можно выполнять в
отдельных процессах через `ACCESS_WORKERS=1..4`; обычный запуск использует
один процесс. Проверка сравнивает последовательный и параллельный результат
с прежним обходом, включая параллельные рёбра, нулевое время, изолированный
узел и путь длиннее 72 часов. Реализация SciPy:
[поиск кратчайших путей](https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.csgraph.dijkstra.html).

### Очистка карты и удаление переписки

Переключение чата очищает выбранный коридор, результат анализа и ручное выделение
дорог, не повторяя команды камеры старых сообщений. Пустое состояние коридора удаляет
его слой и источник MapLibre. Добавленная связь показывается после явного выбора
сценария, а не из последнего задания общей истории. Геометрия базового графа управляется
отдельным переключателем.

Удаление чата хранит явный список удалённых идентификаторов до конца жизни вкладки.
Отложенная запись удаляет только эти ключи, не затрагивая разговоры другой вкладки.
Поздние события прерванного ответа не восстанавливают удалённую сессию. Последний
разговор заменяется пустым, чтобы форма вопроса оставалась доступна.

### Недоступность хранилища после расчёта

Если сохранение завершённого задания возвращает DataUnavailable, результат остаётся в памяти
со статусом completed и отметкой storage_pending. Ошибка записи журналируется отдельно
от ошибки вычисления. До успешного сохранения перезапуск процесса потеряет этот результат;
автоматической повторной записи пока нет. Регрессионный тест воспроизводит таймаут хранилища.

В лаборатории /scenarios используется отдельная матричная модель. Следующие ограничения
относятся к ней; расчёты дорожного графа используют собственный алгоритм.

Связь может оканчиваться не только в опорном городе, но и в любом населённом
пункте (идентификатор ОКТМО из поиска). Для пары опорных городов пересчитывается
вся сеть; у связи с населённым пунктом выигрыш получают сами концы и их цепочки,
транзит прочих поселений через новый пункт не моделируется: матрицы хранят времена
только до 180 городов, а транзит через малый пункт редко входит в кратчайшие пути.
Допущение settlement_links_serve_named_endpoints_only возвращается в ответе,
личный индекс доступности концов связи отдаётся отдельным блоком settlements.

ClickHouse-набор `plexus_scenario` сейчас пуст; лаборатория возвращает ошибку отсутствия
снимка. Адаптер передаёт пустое соответствие ОКТМО строкам матрицы: текущая схема
не хранит эти идентификаторы. Поддержка концов-селений в матричной лаборатории проверена
для файлового набора, но не подтверждена для ClickHouse. Национальный дорожный расчёт
использует отдельный граф и этим ограничением не затронут.
